# Git-Warp v0.4.0

Third public Git-Warp release.

This release adds Windows support, Linux Copy-on-Write via the FICLONE ioctl, a
unified bare-`warp` TUI that toggles between the worktree switcher and the agents
dashboard, an interactive config editor and `warp ls` selector, commit-ish
(tag/SHA) switching, and a broad hardening pass across install, terminal,
process, and cross-platform behavior.

## Highlights

- Unified `warp` TUI: bare `warp` opens the worktree switcher; press `Tab` to
  view live Claude/Codex agent sessions and `Tab` again to return, all in one
  terminal session. `warp agents` still opens the dashboard directly. With
  `agent.enabled=false`, `Tab` shows a notice instead of switching.
- Windows support: a prebuilt Windows binary, `install.ps1` and `uninstall.ps1`,
  and a Windows-aware `warp doctor` (probes, install dir, shell detection, and
  reinstall hint).
- Linux Copy-on-Write: directory clones use the `FICLONE` ioctl on filesystems
  that implement reflinks (btrfs, xfs with `reflink=1`, bcachefs, OCFS2), with a
  functional reflink-support probe. macOS keeps APFS clonefile acceleration.
- Interactive config editor: `warp config --interactive` (`-i`) edits every
  config section in a TUI with validation, atomic save, and unsaved-change
  confirmation. `warp ls --interactive` (`-i`) adds a selection TUI.
- Commit-ish switching: `warp switch` accepts tags and SHAs and pins the
  worktree to the resolved commit via a new local branch.
- Post-create auto-install detects npm, yarn, bun, and Cargo lockfiles in
  addition to pnpm, with a `[post_create] auto_install` opt-out, and
  `init_commands` support `{{branch}}`, `{{repo}}`, and `{{path}}` placeholders.
- Runtime-wired config: `[process]`, `[git].auto_fetch`/`auto_prune`, and
  `[agent].enabled`/`refresh_rate` keys now drive behavior, and nested
  `GIT_WARP_*__*` environment variables override any config section.
- Safety fix: CoW cloning no longer recurses without bound when a worktree is
  stored inside the repository (for example `<repo>/.worktrees/<branch>`).

See the [changelog](../../CHANGELOG.md) for the complete list, including
dependency bumps and CI changes.

## Install Or Upgrade

One command, no Rust/Cargo required:

```bash
curl -fsSL https://raw.githubusercontent.com/denysbutenko/git-warp/main/install.sh | sh
```

Then verify the install:

```bash
warp --version
warp doctor
```

The installer downloads the matching release archive for macOS/Linux and
Intel/Apple Silicon and installs to `~/.local/bin` by default. On Windows, use
`install.ps1` (see [docs/install.md](../install.md)).

Upgrading from v0.3.0 is the same command — re-running the installer overwrites
the existing binary at the install directory. The installer prints any other
`warp` binaries it finds and warns when `warp` on `PATH` resolves to a
different binary than the one just installed. Run `warp doctor` to confirm only
one `warp` is active.

Cargo fallback:

```bash
curl -fsSL https://raw.githubusercontent.com/denysbutenko/git-warp/main/install.sh | GIT_WARP_INSTALL_METHOD=cargo sh
```

Source checkout:

```bash
git clone https://github.com/denysbutenko/git-warp
cd git-warp
git checkout v0.4.0
cargo install --path .
warp --version
warp doctor
```

Expected version output:

```text
warp 0.4.0
```

## Uninstall

```bash
curl -fsSL https://raw.githubusercontent.com/denysbutenko/git-warp/main/uninstall.sh | sh
```

The uninstaller removes `~/.local/bin/warp` (or `$GIT_WARP_INSTALL_DIR/warp`),
also clears installed hooks and shell-config entries, lists any other detected
`warp` installs without touching them, and warns if `warp` is still on `PATH`.
Use `--dry-run` to preview without changing anything. On Windows, use
`uninstall.ps1`. For Cargo installs, also run `cargo uninstall git-warp`.

## Useful Commands

```bash

warp ls --interactive
warp config --interactive
warp --dry-run cleanup --mode merged
warp cleanup --interactive
warp hooks-install --level user --runtime all
warp hooks-status
warp agents
warp release-check --metadata-only --version v0.4.0
```

## Verification

Release prep was checked with:

```bash
cargo fmt --check
cargo test
cargo build --release --bin warp
./target/release/warp --version
./target/release/warp doctor
```

`warp release-check --version v0.4.0` runs the same flow plus metadata checks
against `Cargo.toml`, `CHANGELOG.md`, `docs/releases/v0.4.0.md`,
`docs/install.md`, and `install.sh`.

## Notes

- Copy-on-Write acceleration works on macOS/APFS and on Linux filesystems that
  implement the FICLONE ioctl. Other filesystems fall back to normal Git
  worktree creation.
- The installer resolves the latest release tag from the GitHub API by default.
  Set `GIT_WARP_VERSION` before running it to install a specific tag, or
  `GIT_WARP_INSTALL_DIR` to install somewhere other than `~/.local/bin`.
- Git-Warp is still a `0.x` tool. Use `warp doctor`, `--dry-run`, and focused
  command help when setting it up on a new repo.
