# Git-Warp v0.6.0

Follow-up release to v0.5.0.

This one is mostly hardening and correctness. It closes two argument-injection
paths, makes worktree listing survive odd path bytes, and stops `warp cleanup`
from reporting success when a removal actually failed. The CLI also got split
out of one 2900-line file, and agent discovery stopped re-parsing session files
it already read.

## Highlights

- Git flag injection guard: user-controlled ref and branch names now reach
  `git` behind `--` / `--end-of-options`, so a branch named `-x` (or a crafted
  `--upload-pack=…`) is passed as data instead of being parsed as a flag.
  Covers `worktree add / remove`, `branch -d/-D`, `rev-parse … ^{commit}`,
  `show-ref --verify`, `merge-base --is-ancestor`, and `diff --quiet`.
- Terminal launch hardening: resolved launch commands containing NUL, `\n`, or
  `\r` are rejected, so a `[terminal].init_commands` entry or a substituted
  `{{branch}}` / `{{repo}}` / `{{path}}` value cannot break out of the
  AppleScript string literal on macOS or split a `cmd.exe /K` / PowerShell
  `-Command` argument on Windows.
- Worktree listing reads `git worktree list --porcelain -z` and parses raw
  bytes, so a path containing a newline or non-UTF-8 bytes round-trips verbatim
  instead of splitting one worktree across two bogus rows — which previously
  mis-targeted later `remove_worktree` / `switch` operations.
- `warp cleanup` and the switcher's multi-select batch removal exit non-zero
  when any removal fails, so `set -e`, `&&` chains, and CI jobs stop treating a
  partial cleanup as success. The summary line still prints first.
- `src/cli.rs` (~2900 lines) is split into per-subcommand modules under
  `src/commands/`. `src/cli.rs` now only defines the Clap types and dispatches.
- Agent discovery caches per-file parses keyed by `(path, modified)`, so a
  refresh only re-reads `.jsonl` session files that actually changed.
- Branch completion (`warp __complete branches`) now includes remote-tracking
  branches — exposed by their trailing name, so `origin/feature-x` completes as
  `feature-x` — and tags, deduped against local branches.
- MIT `LICENSE` now ships at the repo root, matching the `license = "MIT"`
  field already declared in `Cargo.toml`.

See the [changelog](../../CHANGELOG.md) for the complete list, including
dependency bumps and the advisories they clear (`RUSTSEC-2026-0009`,
`RUSTSEC-2026-0097`, `RUSTSEC-2026-0190`, `RUSTSEC-2026-0204`,
`RUSTSEC-2026-0253`).

## Install Or Upgrade

One command, no Rust/Cargo required:

```bash
curl -fsSL https://raw.githubusercontent.com/denysbutenko/git-warp/main/install.sh | sh
```

Then verify the install:

```bash
warp --version
warp doctor
```

The installer downloads the matching release archive for macOS/Linux and
Intel/Apple Silicon and installs to `~/.local/bin` by default. On Windows, use
`install.ps1` (see [docs/install.md](../install.md)).

Upgrading from v0.5.0 is the same command — re-running the installer overwrites
the existing binary at the install directory. The installer prints any other
`warp` binaries it finds and warns when `warp` on `PATH` resolves to a
different binary than the one just installed. Run `warp doctor` to confirm only
one `warp` is active.

Cargo fallback:

```bash
curl -fsSL https://raw.githubusercontent.com/denysbutenko/git-warp/main/install.sh | GIT_WARP_INSTALL_METHOD=cargo sh
```

Source checkout:

```bash
git clone https://github.com/denysbutenko/git-warp
cd git-warp
git checkout v0.6.0
cargo install --path .
warp --version
warp doctor
```

Expected version output:

```text
warp 0.6.0
```

## Upgrade Notes

- No config migration. Existing `[cow]`, `[terminal]`, and `[process]` settings
  keep working.
- If a `[terminal].init_commands` entry contains a literal newline or carriage
  return, terminal launch now fails instead of silently splitting the command.
  Split it into separate entries.
- Scripts that call `warp cleanup` and ignored its exit code may now see a
  non-zero status where a removal failed. That status is the fix, not a
  regression — check the summary line for which worktree failed.

```bash
warp switch feature/my-change
warp                     # switcher TUI; press Tab for agent sessions
warp ls --interactive
warp config --interactive
warp shell-config powershell
warp --dry-run cleanup --mode merged
warp cleanup --interactive
warp doctor
warp release-check --metadata-only --version v0.6.0
```

## Verification

Release prep was checked with:

```bash
cargo fmt --check
cargo test
cargo build --release --bin warp
./target/release/warp --version
./target/release/warp doctor
```

`warp release-check --version v0.6.0` runs the same flow plus metadata checks
against `Cargo.toml`, `CHANGELOG.md`, `docs/releases/v0.6.0.md`,
`docs/install.md`, and `install.sh`.

## Notes

- Copy-on-Write acceleration works on macOS/APFS and on Linux filesystems that
  implement the FICLONE ioctl. Other filesystems fall back to normal Git
  worktree creation.
- The installer resolves the latest release tag from the GitHub API by default.
  Set `GIT_WARP_VERSION` before running it to install a specific tag, or
  `GIT_WARP_INSTALL_DIR` to install somewhere other than `~/.local/bin`.
- Git-Warp is still a `0.x` tool. Use `warp doctor`, `--dry-run`, and focused
  command help when setting it up on a new repo.
