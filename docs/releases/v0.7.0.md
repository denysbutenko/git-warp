# Git-Warp v0.7.0

Follow-up release to v0.6.0.

Most of this release makes `warp switch` faster on large pnpm and npm repos.
`warp cleanup --mode merged` now recognizes squash and rebase merges, and an
interrupted install no longer leaves a truncated binary behind.

## Highlights

- On macOS, CoW now clones whole directories with one `clonefile(2)` call
  instead of letting `cp -c -R` walk them file by file. A 127k-file
  `node_modules` went from 28s to 2s. `cp -c -R` is still the fallback when
  `clonefile` refuses (another volume, non-APFS, existing destination).
- When the copied `node_modules` already matches the branch's lockfile byte
  for byte, the post-create hook skips `pnpm install`
  (`node_modules/.pnpm/lock.yaml` vs `pnpm-lock.yaml`) or `npm install`
  (`node_modules/.package-lock.json` vs `package-lock.json`). Other package
  managers still install.
- Executable bits survive the rewrite step, so `node_modules/.bin` shims work
  in new worktrees and `pnpm exec <bin>` stops failing with "Command not
  found".
- `warp cleanup --mode merged` now finds squash- and rebase-merged branches by
  matching patch ids against the base branch and `origin/<base>`. Branches
  merged into any protected branch (`main` and `develop` by default) count as
  merged too, which covers gitflow repos.
- `install.sh` and `install.ps1` stage the new binary next to the old one and
  rename it into place. A failed or interrupted install (disk full, Ctrl-C, a
  running `warp`) leaves the previous binary working.
- `write_atomic` keeps the existing file's mode, so a `0600` config holding a
  token stays `0600` after warp saves it. Parent-directory fsync failures are
  now logged instead of dropped.
- `warp release-check` runs the same `cargo doc -D warnings` gate as CI, and
  the crate declares an MSRV of Rust 1.95.

Internally, `git.rs`, `terminal.rs`, `hooks.rs`, `cow.rs`, the config editor,
`switch`, and `doctor` were split out of single large files into submodules. No
behavior changes came with the splits.

See the [changelog](../../CHANGELOG.md) for the complete list.

## Install Or Upgrade

One command, no Rust/Cargo required:

```bash
curl -fsSL https://raw.githubusercontent.com/denysbutenko/git-warp/main/install.sh | sh
```

Then verify the install:

```bash
warp --version
warp doctor
```

The installer downloads the matching release archive for macOS/Linux and
Intel/Apple Silicon and installs to `~/.local/bin` by default. On Windows, use
`install.ps1` (see [docs/install.md](../install.md)).

Upgrading from v0.6.0 is the same command. Re-running the installer replaces
the existing binary at the install directory. The installer prints any other
`warp` binaries it finds and warns when `warp` on `PATH` resolves to a
different binary than the one just installed. Run `warp doctor` to confirm only
one `warp` is active.

Cargo fallback:

```bash
curl -fsSL https://raw.githubusercontent.com/denysbutenko/git-warp/main/install.sh | GIT_WARP_INSTALL_METHOD=cargo sh
```

Source checkout (Rust 1.95 or newer):

```bash
git clone https://github.com/denysbutenko/git-warp
cd git-warp
git checkout v0.7.0
cargo install --path .
warp --version
warp doctor
```

Expected version output:

```text
warp 0.7.0
```

## Upgrade Notes

- No config migration. Existing `[cow]`, `[terminal]`, and `[process]` settings
  keep working.
- `warp cleanup --mode merged` may now pick up worktrees it skipped before:
  squash- and rebase-merged branches, and branches merged into `develop` while
  the base is `main`. Run `warp --dry-run cleanup --mode merged` first to see
  the list. A merged branch is force-deleted (`git branch -D`) only while it
  still points at the commit cleanup analyzed; if it moved, cleanup falls back
  to `git branch -d`.
- Building from source now needs Rust 1.95 or newer.

## Useful Commands

```bash
warp switch feature/my-change
warp                     # switcher TUI; press Tab for agent sessions
warp ls --interactive
warp config --interactive
warp --dry-run cleanup --mode merged
warp cleanup --interactive
warp doctor
warp release-check --metadata-only --version v0.7.0
```

## Verification

Release prep was checked with:

```bash
warp release-check --version v0.7.0
```

That runs the metadata checks against `Cargo.toml`, `CHANGELOG.md`,
`docs/releases/v0.7.0.md`, `docs/install.md`, and `install.sh`, then `cargo fmt`,
`git diff --check`, `cargo clippy -D warnings`, `cargo test`, `cargo doc -D
warnings`, a release build, and smoke runs of `warp --version`, `--help`, and
`warp doctor`.

## Notes

- Copy-on-Write acceleration works on macOS/APFS and on Linux filesystems that
  implement the FICLONE ioctl. Other filesystems fall back to normal Git
  worktree creation.
- The installer resolves the latest release tag from the GitHub API by default.
  Set `GIT_WARP_VERSION` before running it to install a specific tag, or
  `GIT_WARP_INSTALL_DIR` to install somewhere other than `~/.local/bin`.
- Git-Warp is still a `0.x` tool. Use `warp doctor`, `--dry-run`, and focused
  command help when setting it up on a new repo.
